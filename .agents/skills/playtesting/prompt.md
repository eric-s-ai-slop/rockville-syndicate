# One-chapter playtest prompt

> Playtest chapter `<chapter-index>` from its beginning through its natural terminal state. First read `.agents/skills/playtesting/SKILL.md`; it is the operating contract. Launch one persistent session with `npm run agent -- --chapter <chapter-index> --repl --checkpoints --playtest --out "qa/<chapter-id>" --transcript "qa/<chapter-id>/session.jsonl"`, using the chapter config's `id` for `<chapter-id>`.

> Use `omega-agent-v1` JSON commands with a unique `cmd_id` for every meaningful action. Send exactly one newline-terminated JSONL command at a time and wait for its correlated receipt. Use `advance` as the main loop and route only from its named status: `walk-control`, `choice-present`, `walk-target-present`, `mode-active`, `ambient-dialogue`, or `chapter-ended`. Do not add routine `state`, `observe`, or `diff` calls when the `advance` receipt already answers the routing question.

> When a `visual_checkpoint` appears, stop, inspect its original PNG, and immediately send `reviewcheckpoint <id> clear|issue-found|inconclusive <observation-note>`. Every verdict, including `clear`, requires a concrete note about visible actors, layout, text, effects, or UI. The CLI blocks progression while checkpoints are pending. Treat one checkpoint containing multiple `transitions` as evidence for all listed transitions. Treat `captureMissed:true` as Not verified. Do not duplicate an adequate checkpoint with another screenshot.

> At a choice, save once and inspect `savestate.branchSafe`. Restore between options only when it is true; otherwise use a fresh natural run. Follow only branch-unique content until convergence or another interactive boundary. For a foreground mode, read its instructions, exercise its core input through at least one coherent normal attempt, inspect active-play feedback, and then continue through its post-mode story. A background mode must coexist with foreground progress and tear down correctly; never resolve it with `winmode` or `losemode`.

> There is no command named `_bypass` or `bypass`. The only permitted bypasses are exactly `skipbeat 1` for a proven stuck non-mode beat and `winmode`/`losemode` for a blocking foreground mode after normal input. Before either, capture `observe --shot`, `beats`, and `text`, then quote the exact command and error; never chain `skipbeat 1` through a minigame. A bypass makes `playtest_integrity` `partially-bypassed`; preserve `bypasses` and `audit`, continue only for downstream diagnosis, and never claim verified completion.

> Prefer automatic checkpoints and compact `advance` receipts. Use `text` only for wording, `targets` only for a walk objective, annotation only for placement/depth questions, telemetry only for suspected performance, and a short `gifstart`/`gifstop` capture only for motion defects. Do not record a whole-session GIF by default.

> Record each confirmed defect or friction point immediately with the JSON-only `recordfinding` action and its eight args: severity, category (`visual|friction|flow|mode|content|audio|performance|other`), title, runtime location, reproduction, expected, actual, and evidence. Link visual findings with `checkpoint:<id>`. Use `dismissfinding <id> <reason>` if disproven. Do not repeatedly edit report prose while playing; the harness keeps `progress.md` and `progress.json` current in `qa/<chapter-id>/` without model work.

> Do not stop after a minigame. At `chapter-ended`, inspect the terminal presentation, run `wait 2300` once for the completion transition, review any new checkpoint, and confirm stale story/mode UI is gone. Then `quit`. `visual_qa.pending` must be empty, terminal coverage must be observed, and `playtest_integrity` must be natural for `completion_status: verified`. A terminal beat with incomplete visual QA is not completion: `quit`/EOF fails closed and exits nonzero; incomplete coverage or integrity also fails.

> After quitting, generate the report once with `npm run agent:write-report -- qa/<chapter-id>/report.md qa/<chapter-id>/session.jsonl`; keep the report, screenshots, transcript, progress files, and other playtest artifacts together in `qa/<chapter-id>/`. Then run `npm run agent:verify-report -- qa/<chapter-id>/report.md qa/<chapter-id>/session.jsonl`. Do not claim success unless it passes.

> If the toolkit itself blocks honest completion, create or update `docs/toolkit_complaints.md` directly with the exact command, error, runtime state, evidence paths, workaround or missing capability, and downstream coverage impact; do not ask for permission again. Keep game defects in the chapter report and toolkit defects in the complaint file.
